# BaltOIL

Платформа учёта и доставки топлива для СЗТК: заявки клиентов, рейсы и склад, документы,
чаты и звонки, мобильное приложение для водителей и менеджеров и GPS-мониторинг
автотопливозаправщиков на самодельных трекерах.

| Часть | Что это | Где в репозитории |
|---|---|---|
| **Веб** | CRM для менеджеров, админов, водителей и клиентов (SPA) | [`frontend/`](frontend) |
| **Бэкенд** | 6 микросервисов на FastAPI + PostgreSQL + Redis | `auth_service`, `order_service`, `delivery_service`, `chat_service`, `notification_service`, `call_service` |
| **Мобильное приложение** | Android-приложение на Flutter | [`mobile_app/`](https://github.com/S0m1k/BaltOIL/tree/mobile/mobile_app) — актуальная версия в ветке `mobile` |
| **GPS-трекеры** | Arduino + GPS + GSM-модем, шлют точки на приёмник в `delivery_service` | [`docs/gps_tracker_totp.md`](docs/gps_tracker_totp.md), [`SPEC_SPRINT_2026_09_GPS.md`](SPEC_SPRINT_2026_09_GPS.md) |

Роли пользователей: `admin`, `manager`, `driver`, `client`. Что видит и может каждая роль,
определяется на бэкенде — веб и приложение только отображают.

## Архитектура

```
   Браузер (SPA)      Приложение (Flutter)              GPS-трекер
        │                     │                     (Arduino + SIM900A)
        └───────┬─────────────┘                              │ HTTP, порт 8010
                ▼                                            ▼
        nginx (TLS 443, единый шлюз /api/<сервис>/)   nginx (порт 8010, без TLS)
                │                                            │
   ┌────────┬───┴────┬─────────┬──────────┬──────────┬───────┴────┐
 auth     order   delivery   chat   notification   call      (delivery)
 :8001    :8002    :8003     :8004     :8005       :8006      /gps/ingest
   │        │        │         │         │           │
   └────────┴────────┴────┬────┴─────────┴───────────┘
                          ▼
             PostgreSQL (БД на сервис)  ·  Redis (события, WebSocket)  ·  LiveKit (звонки)
```

- Сервисы независимы: у каждого своя БД и свои миграции (Alembic), общаются по HTTP и через
  события Redis. Токены проверяются локально общим `JWT_SECRET_KEY`.
- Веб и приложение ходят через **один TLS-шлюз на 443** с префиксами `/api/auth/`, `/api/order/`,
  `/api/delivery/`, `/api/chat/`, `/api/notif/`, `/api/call/`. Порты 8001–8006 напрямую не нужны.
- Подробнее по сервисам и эндпоинтам — [`ARCHITECTURE.md`](ARCHITECTURE.md).

| Сервис | Порт | За что отвечает |
|---|---|---|
| `auth_service` | 8001 | пользователи, вход, JWT с ротацией refresh-токенов, организации клиентов |
| `order_service` | 8002 | заявки, тарифы, оплаты, финансы, документы, договоры, перевозки |
| `delivery_service` | 8003 | ТС, рейсы, склад и ёмкости, зоны доставки, отчёты, **GPS** |
| `chat_service` | 8004 | диалоги, группы, вложения, поиск по сообщениям, WebSocket |
| `notification_service` | 8005 | уведомления в приложении, email, push (FCM) |
| `call_service` | 8006 | аудио-звонки поверх LiveKit |

Стек: Python 3.12, FastAPI, SQLAlchemy 2 (async), Alembic, PostgreSQL 16, Redis 7, nginx,
LiveKit. Веб — один `index.html` на чистом JS + Leaflet. Мобильное приложение — Flutter.

## Веб

Один файл [`frontend/index.html`](frontend/index.html), отдаётся nginx; собирать ничего не нужно.

- **Заявки** — три вида: физлицо, юрлицо, внутренняя ТТН-Л; отдельные **заявки на перевозку**
  со справочниками нефтебаз и объектов клиентов. Цена считается по тарифам и зонам доставки,
  итог — с округлением до копейки.
- **Документы** — счета (предварительный и финальный), УПД, ТТН, договоры поставки,
  доверенность М-2; PDF генерируются на сервере и уходят клиенту в чат.
- **Рейсы, склад, ёмкости** — журнал рейсов, остатки топлива, ёмкости со счётчиками колонок,
  переливы и корректировки, отчёты водителей и складские отчёты в XLSX.
- **Финансы** — платежи, сводки и выгрузки XLSX по видам заявок.
- **Клиенты и организации**, пользователи, справочник видов топлива, тарифы, зоны доставки на карте.
- **Чат** — диалоги клиент↔менеджер, клиент↔водитель по заявке, группы сотрудников, личные
  чаты, вложения, ответы и закрепление, статусы прочтения, **поиск по сообщениям**.
- **Звонки** — аудио внутри чата.
- **Транспортные средства** (для админа): список ТС, **GPS-мониторинг** и **Трекеры** — см. ниже.
- Журнал действий по заявке, уведомления в реальном времени (SSE).

## Мобильное приложение

Каталог [`mobile_app/`](https://github.com/S0m1k/BaltOIL/tree/mobile/mobile_app), Flutter (Dart 3.11+). Актуальная разработка — в ветке
**`mobile`** (в `master` лежит устаревшая копия). Сборка, подпись и настройка Firebase — в
[`BUILD.md`](https://github.com/S0m1k/BaltOIL/blob/mobile/mobile_app/BUILD.md).

- Те же роли и разделы, что в вебе: заявки, перевозки, клиенты, организации, рейсы, склад и
  ёмкости, финансы, тарифы, отчёты, зоны, пользователи.
- **Чат** с очередью отправки без сети (offline-outbox) и защитой от дублей, фото на весь
  экран с зумом, **поиск по сообщениям**, галочки прочтения.
- **Звонки** (LiveKit + CallKit-экран входящего), **push-уведомления** (FCM): тап ведёт в
  нужный чат или заявку.

```bash
cd mobile_app
flutter pub get
flutter test
flutter build apk --release        # по умолчанию смотрит на прод, --dart-define не нужны
```

Локально против своего стенда:
`flutter run --dart-define=API_HOST=10.0.2.2 --dart-define=API_DIRECT_PORTS=true --dart-define=ALLOW_BAD_CERTS=true`.

## GPS-мониторинг

Админ видит на карте текущее положение машин и маршрут за любую дату месяца: пробег, время в
движении, скорости, условная погрешность по числу спутников. История хранится 31 день.

**Трекер** — Arduino Nano + GPS-модуль NEO-6M + GSM-модем SIM900A (2G). Раз в интервал шлёт
на приёмник одну строку:

```
<номер устройства> <код TOTP> <широта> <долгота> <спутники>
SZTK-01 48291376 59.938732 30.312345 9
```

- **Приём** — `delivery_service`, эндпоинт `/api/v1/gps/ingest`. Наружу торчит отдельным
  портом **8010** (обычный HTTP: GSM-модем TLS не умеет); через общий шлюз 443 этот путь закрыт.
  Ответ — `OK` или `ERR:<код>`. Разбор всеядный: разделитель, JSON, форма и query-параметры.
- **Подтверждение трекера** — код TOTP (RFC 6238: HMAC-SHA1, шаг 30 с, **8 цифр**, время
  берётся с GPS). Секрет выдаётся в админке («Транспортные средства → Трекеры → Настроить»),
  в БД хранится зашифрованным. Неверные коды ограничиваются — защита от перебора.
- **Защита открытого порта** — строгий формат, антифлуд по устройству, отсев невозможных
  координат, лимит автозаведения неизвестных номеров, обрезка тела до чтения.
- **Погрешность** считается условно по числу спутников: 3 → ±60 м, 5 → ±20 м, 7 → ±9 м,
  11+ → ±4 м; точки без фикса не сохраняются, но трекер отмечается «на связи».
- Журнал приёма в админке показывает последние сырые сообщения — удобно, когда «трекер молчит».

Прошивка (формат строки, код для Arduino, контрольные значения RFC для проверки) —
[`docs/gps_tracker_totp.md`](docs/gps_tracker_totp.md). Проверка без железа:

```bash
python scripts/gps_sim.py --host <хост> --port 8010 --device SZTK-01 --count 1
```

## Локальный запуск

Нужны Docker, `docker compose` и `openssl`. Пошагово (env-файлы, самоподписанный TLS, сиды,
тестовые логины) — [`DEV_SETUP.md`](DEV_SETUP.md).

```bash
docker compose up -d --build
make seed          # тестовые данные; запрещено при APP_ENV=production
```

Файлы `.env`, каталог `tls/` и `docker-compose.override.yml` в git не попадают — создаются
локально. `JWT_SECRET_KEY` и `INTERNAL_API_SECRET` должны быть одинаковыми во всех сервисах.

## Тесты

```bash
cd delivery_service && python -m pytest     # GPS-приёмник и TOTP — без БД
cd chat_service     && python -m pytest     # права на чаты, поиск

cd auth_service     && python -m pytest
cd mobile_app       && flutter test     # в ветке mobile
```

## Безопасность

Секреты (`.env`, ключи подписи, `google-services.json`, TLS-ключи) в репозиторий не
кладутся. Приёмник GPS открыт в интернет без TLS сознательно — модем его не умеет; вместо
этого трекер подтверждает себя кодом TOTP, а сервер режет частоту и мусор. Остаточные риски
описаны в [`DEPLOY_NOTES_2026_09.md`](DEPLOY_NOTES_2026_09.md).
