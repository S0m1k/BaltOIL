# TOTP для GPS-трекера — что добавить в прошивку

Сервер BaltOIL (с 19.09.2026) принимает от трекера 8-значный код TOTP и по нему убеждается,
что точку прислал именно этот трекер, а не сканер из интернета, подбирающий номера устройств.
Координаты не подписываются — так договорились; код считается только от времени.

## Что поменять в прошивке

1. **Адрес приёма:** `http://5.42.118.110:8010/`. Путь и метод (POST/GET) любые.
2. **Строка сообщения:** код ставится сразу после номера устройства:
   ```
   SZTK-01 48291376 59.938732 30.312345 9
   ```
   Разделитель — пробел, запятая или `;`. Остальное как сейчас.
3. **Код:** стандартный TOTP по RFC 6238 — HMAC-SHA1, шаг 30 секунд, **8 цифр** (не 6),
   время — UTC с GPS. Точки без кода или с неверным кодом сервер отвечает `ERR:AUTH`.
4. **Секрет:** у каждого трекера свой. Выдаётся в админке: «Транспортные средства» →
   «Трекеры» → «Настроить» → «Выдать секрет TOTP». Там же сразу готовый массив
   `const uint8_t TOTP_SECRET[20] = {...};` — вставить в прошивку этого трекера.
   Показывается один раз; потерялся — «Перевыдать».

Пока секрет трекеру не выдан, сервер принимает его точки без кода, как раньше. Поэтому
порядок такой: залить новую прошивку → выдать секрет в админке → вставить массив → залить
ещё раз. Или сначала выдать секрет, а потом прошить — просто точки до прошивки будут
отклоняться.

## Код для Arduino

Нужен только SHA1 с HMAC — например, `sha1.h` из библиотеки **TOTP-Arduino** (lucadentella)
или **Cryptosuite**. Готовая функция `getCode()` из TOTP-Arduino **не подходит**: она
всегда отдаёт 6 цифр, а сервер ждёт 8. Ниже — полный расчёт, ~2–3 КБ флеша, ~100 байт ОЗУ.

```cpp
#include "sha1.h"  // из TOTP-Arduino или Cryptosuite: Sha1.initHmac / write / resultHmac

const char DEVICE_ID[] = "SZTK-01";
// Из админки, у каждого трекера свой:
const uint8_t TOTP_SECRET[20] = {0x00, 0x00 /* ... 20 байт ... */};

// Unix-время из даты/времени GPS (UTC). Алгоритм days_from_civil (H. Hinnant);
// все промежуточные значения в 32 битах — на AVR int всего 16 бит.
uint32_t unixTime(uint16_t y, uint8_t mo, uint8_t d, uint8_t h, uint8_t mi, uint8_t s) {
  y -= mo <= 2;
  int32_t era = y / 400;
  uint32_t yoe = y - era * 400;
  uint32_t doy = (153UL * (mo + (mo > 2 ? -3 : 9)) + 2) / 5 + d - 1;
  uint32_t doe = yoe * 365 + yoe / 4 - yoe / 100 + doy;
  int32_t days = era * 146097L + (int32_t)doe - 719468L;
  return (uint32_t)days * 86400UL + h * 3600UL + mi * 60UL + s;
}

// TOTP по RFC 6238: HMAC-SHA1, шаг 30 с, 8 цифр. out — буфер на 9 символов.
void totpCode(uint32_t unixSeconds, char out[9]) {
  uint32_t step = unixSeconds / 30;
  Sha1.initHmac(TOTP_SECRET, sizeof(TOTP_SECRET));
  // 8-байтный счётчик big-endian; старшие 4 байта — нули (хватит до 2106 года)
  for (uint8_t i = 0; i < 4; i++) Sha1.write((uint8_t)0);
  Sha1.write((uint8_t)(step >> 24));
  Sha1.write((uint8_t)(step >> 16));
  Sha1.write((uint8_t)(step >> 8));
  Sha1.write((uint8_t)step);
  uint8_t* h = Sha1.resultHmac();
  uint8_t off = h[19] & 0x0F;
  uint32_t bin = ((uint32_t)(h[off] & 0x7F) << 24) | ((uint32_t)h[off + 1] << 16)
               | ((uint32_t)h[off + 2] << 8) | h[off + 3];
  snprintf(out, 9, "%08lu", (unsigned long)(bin % 100000000UL));
}

// Сборка строки. latStr/lonStr — координаты строкой с 6 знаками, как сейчас
// (snprintf на AVR не печатает float через %f — нужен dtostrf или своя строка).
void buildMessage(char* buf, size_t size, uint16_t y, uint8_t mo, uint8_t d,
                  uint8_t h, uint8_t mi, uint8_t s,
                  const char* latStr, const char* lonStr, uint8_t sats) {
  char code[9];
  totpCode(unixTime(y, mo, d, h, mi, s), code);
  snprintf(buf, size, "%s %s %s %s %u", DEVICE_ID, code, latStr, lonStr, sats);
}
```

С TinyGPS++ дата и время берутся так: `gps.date.year()`, `gps.date.month()`, `gps.date.day()`,
`gps.time.hour()`, `gps.time.minute()`, `gps.time.second()` — и только когда
`gps.date.isValid() && gps.time.isValid()`, то есть при фиксе. Код считать в момент отправки.

## Как проверить до поездки

- **Контрольный пример из RFC 6238:** секрет — байты строки `12345678901234567890`
  (`{0x31,0x32,…,0x39,0x30}`), время `59` → код `94287082`, время `1111111109` →
  `07081804`. Если Arduino выдаёт то же — расчёт верный. Сервер проверен на тех же
  значениях (тесты `delivery_service/tests/test_gps_totp.py`).
- **Живая проверка:** в админке при выдаче секрета показан base32 — его можно добавить
  в любое приложение-аутентификатор (Google Authenticator, Aegis) с настройками «8 цифр,
  30 секунд». Коды на телефоне и в мониторе порта Arduino должны совпадать.
- **Ответ сервера:** `OK` — принято; `ERR:AUTH` — нет кода, код неверный или часы
  сбились; `ERR:NOFIX` — нет спутников. Всё, что пришло, видно в админке:
  «Трекеры» → «Журнал приёма».

## Ограничения

- Допуск по времени ±30 секунд. С GPS-временем это с запасом; если трекер отправляет
  точки, накопленные без связи, код всё равно считается на момент отправки — это нормально.
- После 10 неверных кодов за 10 минут сервер перестаёт проверять этот трекер до конца окна
  (защита от перебора). Значит, трекер с неправильным секретом на 10 минут «замолкает» —
  ищите причину в журнале приёма.
